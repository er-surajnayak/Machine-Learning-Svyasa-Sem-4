ML Svyasa/Module 1/Data Types in ML

ML only understands
numbers.
Everything else must convert.

ML doesn't understand emotions, words, or "good vibes." It only understands numbers. This topic explains the 3 core data types and why treating them incorrectly breaks your model.

01 · The core idea

Why data types matter in ML

When we build ML models, the type of data we feed matters enormously. Different data types behave differently — and if we treat them incorrectly, the model learns the wrong relationships.

🔢
Numerical

Measurable quantities — age, salary, CGPA

🏷️
Categorical

Names & labels — branch, city, blood group

📊
Ordinal

Ordered labels — Low/Medium/High, grades

Memory trick: "What type is this?" → Categorical. "How much?" → Numerical. Has order but no exact gap → Ordinal.
02 · First type

Numerical Data

MeasurableDirect to model

Numbers with real magnitude. If someone studies 10 hours and another studies 5, the first has genuinely done double. The numbers carry mathematical meaning.

Quick test: Can I break this into smaller decimals meaningfully? Yes → Continuous. No → Discrete. You can have height 170.2 cm. You can't have 2.3 internships.
03 · Second type

Categorical Data

Labels & namesNeeds encoding

These are names or labels — not numbers, and not ordered. The model cannot understand text, so we must convert categories to numbers carefully.

The trap: If you encode CSE=1, ECE=2, MECH=3 — the model assumes MECH > ECE > CSE. That's wrong! There's no ranking between branches. This is why naive number assignment breaks models.
Examples of categorical features
FeatureValuesProblem if numbered
BranchCSE, ECE, MECHModel thinks MECH(3) > CSE(1)
CityBangalore, Delhi, MumbaiNo ordering between cities
Blood GroupA, B, AB, OAB(3) ≠ better than A(1)
PlacedYes, NoThis one IS safe as 1/0 — only 2 values

The solution is One-Hot Encoding — covered in detail in Topic 4 (Data Processing). Instead of one column with numbers, we create one column per category using 0s and 1s.

04 · Third type

Ordinal Data

Has orderNo exact gap

A special case between categorical and numerical. There is a meaningful order, but we can't say exactly how much gap there is between levels.

Examples

Communication skillLow < Medium < High
T-shirt sizeS < M < L < XL
Rating★ < ★★ < ★★★★★
GradeC < B < A < A+

The key distinction

Order exists?Yes ✓
Exact numeric gap?No ✗
Is High = 2× Medium?Not necessarily
Safe to encode as 1,2,3?Careful ⚠
Ordinal vs Categorical: Both are labels. But ordinal has a clear ranking (Low < Medium < High). Categorical has no ranking (CSE is not greater or lesser than ECE). The difference determines how you encode it.
05 · Beyond tables

Text, Image & Audio — everything is still numbers

ML doesn't only work with neat tables. Real-world ML works with text, images, and sound. But behind the scenes — it all becomes numbers.

📝
Text Data
Emails, tweets, reviews, chat messages
▶

Text must be converted to numbers before any model can process it. The model doesn't "read" — it sees numerical representations.

Examples

Spam detectionemail → numbers
Sentiment analysisreview → score
Chatbotsmessage → vector

How it converts

Techniques like TF-IDF, Word2Vec, or tokenization turn each word into a number or vector. "spam" might become [0.8, 0.1, 0.3…]

🖼️
Image Data
Photos, X-rays, satellite images, faces
▶

Images look visual to us. To ML, they are just huge matrices of pixel values — each pixel is a number from 0 to 255.

A 28×28 grayscale image = matrix of 784 numbers (0–255)
A 100×100 RGB image = 3 matrices × 10,000 = 30,000 numbers
This is why image ML models are computationally expensive — each image is tens of thousands of input features.
🎵
Audio Data
Voice assistants, music recognition, speech-to-text
▶

Voice assistants don't "hear" words like humans do. Audio is converted into waveforms → frequencies → numerical feature vectors before any ML model processes it.

Sound wave→ Waveform samples (numbers)
Waveform→ Frequency spectrum (FFT)
Spectrum→ Feature vector → ML model
The big realization: Text, images, audio, video — everything must be converted into numeric form before ML can process it. That conversion step is the real skill. The algorithms are just math on top of those numbers.
