Model Evaluation
Metrics

Your model says it's 99% accurate. But does it actually work? This topic breaks down every metric you need to truly measure a classifier — from the confusion matrix to ROC curves.

01 · The problem

Why accuracy alone lies

Let's start with a story. A weather app in Bangalore predicts "No Rain" every single day of the year. Out of 365 days, 300 are actually dry. So the app gets 300 out of 365 correct — that's 82% accuracy. Impressive? Not at all. It's completely useless for deciding whether to carry an umbrella.

The trap: When data is imbalanced — more of one class than the other — a model that just predicts the majority class every time will score high accuracy while learning absolutely nothing.

We need metrics that measure what we actually care about. That's where the confusion matrix comes in.

02 · The foundation

The Confusion Matrix

Every prediction a classifier makes falls into one of four boxes. The confusion matrix lays them all out. Think of a doctor testing patients for a disease — there are only four possible outcomes.

Analogy — The Doctor's Test: Correctly catching a sick patient → True Positive. Correctly clearing a healthy one → True Negative. Alarming a healthy person → False Positive (false alarm). Missing a sick patient → False Negative (missed catch). Every single prediction fits one of these four boxes.

03 · Two opposing forces

Precision & Recall

These two metrics pull in opposite directions. Making one better often makes the other worse. Understanding both is critical.

Analogy — The Detective vs The Net: A careful detective (high precision) arrests only people they're very sure about — rarely wrong, but may let some criminals escape. A wide fishing net (high recall) catches almost every criminal in the city — but also hauls in some innocent people. You rarely get both at once.
Precision
Precision = TP / (TP + FP)

Of everything the model called "Positive" — how many actually were?

PenalizesFalse Positives (false alarms)
Use whenFP is costly (spam filter)
ExampleDon't delete legit emails
Recall
Recall = TP / (TP + FN)

Of all the actual Positives that exist — how many did the model catch?

PenalizesFalse Negatives (missed catch)
Use whenFN is costly (cancer detection)
ExampleNever miss a sick patient
The tradeoff in practice: Lower your classification threshold → more things predicted Positive → Recall goes up (catch more) but Precision drops (more false alarms). Raise your threshold → fewer Positive predictions → Precision goes up but Recall drops. This is the precision-recall tradeoff.

Also known as Sensitivity (Recall) and Specificity = TN / (TN + FP) — how well it identifies actual negatives.

04 · The balance

F1-Score

We need one number that captures both precision and recall. The F1-Score does this using the harmonic mean — not the regular average.

Analogy — The Strict Judge: If Precision = 1.0 and Recall = 0.0, the arithmetic mean is 0.5 — that looks okay. But the F1-Score is 0. The harmonic mean refuses to reward extreme imbalance. A model that's amazing at one metric but useless at the other scores close to zero on F1. It forces the model to be good at both.
F1 = 2 × (Precision × Recall) / (Precision + Recall)

05 · The full picture

ROC Curve & AUC

Every classifier outputs a probability (e.g. 0.73), not just a label. You then pick a threshold: if prob ≥ 0.5 → Positive. But what if you change that threshold?

Analogy — The Volume Knob: Lowering the threshold is like turning up the sensitivity dial — you catch more true positives (higher recall) but also flag more false positives. Turning it up catches fewer but with more confidence. The ROC curve plots this tradeoff at every possible threshold. AUC (Area Under the Curve) summarizes the whole curve in one score.

AUC is threshold-independent — it measures overall discrimination power regardless of where you set the cutoff. Perfect for comparing two models head-to-head.

06 · Decision guide

Choosing the right metric

There's no universally best metric. The right one depends on which type of error costs more in your specific problem.

The key question to ask: In my problem, is a False Positive (false alarm) or a False Negative (missed detection) more dangerous or costly?

Click each case below to see the reasoning:

+
Cancer / Disease Detection
›
Worst mistake: Missing a sick patient (False Negative) → disease goes untreated
Acceptable mistake: False alarm — patient gets an extra test, not ideal but survivable
Metric to optimize: Recall (Sensitivity) — catch every possible positive
Logic: Minimize FN at the cost of more FP
✉
Spam Email Filter
›
Worst mistake: Flagging a legitimate email as spam (False Positive) → user misses important mail
Acceptable mistake: Letting some spam through — annoying, not disastrous
Metric to optimize: Precision — only flag things you're very sure about
Logic: Minimize FP at the cost of some FN
₹
Fraud Detection
›
Worst mistake: Both matter — missing fraud costs money; blocking real users destroys trust
Balance needed: You can't afford to be extreme on either side
Metric to optimize: F1-Score — harmonic mean of precision and recall
Logic: Best single number when both error types matter equally
≈
Comparing Two Models
›
Goal: Which model is fundamentally better, independent of threshold choice?
Problem with F1: Depends on threshold — comparing at different thresholds is unfair
Metric to use: AUC-ROC — evaluates across all thresholds
Logic: Higher AUC = model ranks positives above negatives more consistently

08 · Check your understanding

Quick quiz

Three questions — test yourself on what you've learned.

1. A fraud detection model predicts "Not Fraud" for all 10,000 transactions (9,900 legit, 100 fraudulent). What is its accuracy?
A. 50% — misses half the cases
B. 1% — catastrophic failure
C. 99% — but catches zero fraud ✓
D. 90% — good enough for production
9,900 correct out of 10,000 = 99% accuracy. Looks great on paper. Catches zero fraud. This is why accuracy alone is misleading with imbalanced classes. ✓
2. A cancer detection system must never miss a sick patient — it's okay to send some healthy people for extra tests. Which metric should be maximized?
A. Precision — avoid false alarms
B. Accuracy — overall correctness
C. Recall — catch every sick patient ✓
D. AUC — compare against other models
Missing a sick patient is a False Negative — the most dangerous error here. Recall = TP / (TP + FN). Maximize Recall to minimize FN, even if FP (false alarms) increases. ✓
3. Precision = 1.0, Recall = 0.0. What is the F1-Score?
A. 0.5 — the arithmetic average
B. 0.0 — harmonic mean punishes extremes ✓
C. 1.0 — precision is perfect
D. Undefined — can't compute with 0
F1 = 2 × (1.0 × 0.0) / (1.0 + 0.0) = 0. The harmonic mean gives 0 whenever either metric is 0. This is exactly what makes F1 superior to a simple average — it refuses to reward models that are useless at one thing. ✓
