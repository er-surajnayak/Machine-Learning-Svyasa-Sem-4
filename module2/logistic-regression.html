Logistic
Regression

Despite its name, it's a classifier. Logistic regression squashes any real number into a probability between 0 and 1 using the sigmoid function — then draws a linear decision boundary to separate classes.

01 · The starting point

Why not just use linear regression?

When the target is a category (spam/not spam, disease/healthy, fraud/legit), linear regression produces unbounded numbers that can exceed 1 or go below 0. Those aren't valid probabilities, and the decision threshold becomes arbitrary and unstable.

The problem: If we predict "probability of spam" using y = w₀ + w₁x, what stops the model from outputting 2.7 or −0.3? Probabilities must live in [0, 1]. Linear regression has no such constraint — it's the wrong tool for the job.

The fix is elegant: take the linear output z = w₀ + w₁x₁ + w₂x₂ + … and pass it through the sigmoid function σ(z), which squashes any real number into (0, 1). That output becomes the predicted probability.

02 · The key function

The sigmoid function

The sigmoid (or logistic) function is the heart of the algorithm. It maps any real number to a value strictly between 0 and 1 — making it perfect for representing probability.

σ(z) = 1 / (1 + e−z)
where z = w₀ + w₁x₁ + w₂x₂ + … + wₙxₙ (the linear combination)
Analogy — The dimmer switch: Linear regression is like an on/off light switch — it jumps abruptly. The sigmoid is like a dimmer. As z goes from −∞ to +∞, the output smoothly transitions from 0 (definitely off) through 0.5 (uncertain) to 1 (definitely on). There are no sudden jumps — just a graceful S-shaped curve.

03 · Where the line is drawn

Decision boundary

We classify a point as class 1 if σ(z) ≥ 0.5, and class 0 otherwise. Since σ(z) = 0.5 when z = 0, the decision boundary is exactly the set of points where w₀ + w₁x₁ + w₂x₂ = 0 — a straight line (or hyperplane in higher dimensions).

Key insight: Logistic regression always produces a linear decision boundary in the original feature space. It cannot learn a circular or curved boundary unless you manually add polynomial features (e.g., x², x₁·x₂). This is its fundamental limitation — and why SVMs with kernels or neural networks are needed for complex boundaries.

04 · Learning from mistakes

Log-loss & the cost function

Logistic regression doesn't use MSE (mean squared error). Instead it uses log-loss (binary cross-entropy), which severely penalises confident wrong predictions and gently rewards uncertain correct ones.

J(w) = −(1/m) Σ [ yᵢ · log(ŷᵢ) + (1−yᵢ) · log(1−ŷᵢ) ]

When y = 1: Loss = −log(ŷ) → huge penalty if ŷ → 0
When y = 0: Loss = −log(1 − ŷ) → huge penalty if ŷ → 1
Why not MSE? With sigmoid outputs, MSE creates a non-convex loss landscape full of local minima — gradient descent gets stuck. Log-loss is convex for logistic regression, meaning there's exactly one global minimum and gradient descent is guaranteed to find it.
CORRECT PREDICTION
WRONG PREDICTION
MSE vs LOG-LOSS

If true label y = 1 and model predicts ŷ = 0.9:

Loss = −log(0.9) = 0.105    ← small, acceptable

If true label y = 1 and model predicts ŷ = 0.99:

Loss = −log(0.99) = 0.010    ← tiny, very confident & correct

When the model is confidently correct, log-loss is close to zero. Good predictions are barely penalised.

If true label y = 1 but model predicts ŷ = 0.1:

Loss = −log(0.1) = 2.303    ← large penalty!

If true label y = 1 but model predicts ŷ = 0.01:

Loss = −log(0.01) = 4.605    ← very large penalty!

Confident wrong predictions are punished exponentially. The closer ŷ gets to 0 when y=1, the more the loss explodes. This forces the model to be careful about certainty.

Log-loss (convex)
MSE (non-convex)

Log-loss is convex — one clean bowl shape. MSE with sigmoid is bumpy with local minima. Gradient descent on log-loss always finds the global minimum.

05 · The learning algorithm

Gradient descent

Logistic regression is trained by minimising the log-loss using gradient descent — repeatedly nudging each weight in the direction that reduces the cost function.

Update rule (for each weight wⱼ):

wⱼ ← wⱼ − α · (∂J/∂wⱼ)

where α = learning rate, ∂J/∂wⱼ = (1/m) Σ (ŷᵢ − yᵢ) · xᵢⱼ
Beautiful result: The gradient formula for logistic regression looks identical to linear regression — (ŷ − y) · x. The difference is that ŷ is now σ(z) instead of z directly. Same update rule, different model output. This is why logistic regression is so elegant.
The training loop — step by step
Step 1 — Forward passCompute z = Xw, then ŷ = σ(z) for all training points
Step 2 — Compute lossJ = −(1/m) Σ [y·log(ŷ) + (1−y)·log(1−ŷ)]
Step 3 — BackpropGradient ∂J/∂w = (1/m) · Xᵀ · (ŷ − y)
Step 4 — Updatew ← w − α · gradient
Step 5 — RepeatUntil convergence or max iterations reached

06 · Preventing overfitting

08 · Beyond binary

Multi-class via softmax

Binary logistic regression handles two classes. For K classes, we replace the sigmoid with the softmax function — which converts K raw scores into K probabilities that sum to exactly 1.

softmax(zₖ) = e^zₖ / Σⱼ e^zⱼ

One weight vector wₖ per class → z₁, z₂, …, z_K raw scores
Predict: class = argmax_k softmax(zₖ)
Analogy — Voting: Each class casts a "vote" equal to e^(its score). The final probability of each class is its fraction of the total votes. Exponential ensures all values are positive, and dividing by the sum ensures they add up to 1.

09 · Context & comparison

Logistic Regression vs Decision Tree

Two popular classifiers with very different mechanics. Choosing between them depends on data size, interpretability needs, and boundary complexity.

PropertyLogistic RegressionDecision Tree
Decision boundaryLinear (or poly features)Axis-aligned rectangles
InterpretabilityWeights show feature importanceVery visual — tree structure
Probability outputsCalibrated probabilities ✓Less calibrated
Overfitting riskLow (with regularization)High (without pruning)
Handles non-linearityNeeds manual feature engineeringYes, naturally ✓
Missing valuesNeeds imputation ✗Can handle natively ✓
Feature scaling neededYes (affects gradient descent)No — splits are relative
Training speedFast (convex optimisation)Fast (greedy splits)
Best forLinearly separable, probabilities neededComplex patterns, non-numeric
?
When should I choose logistic regression?
›
Choose logistic regression when:
→ You need well-calibrated probability outputs (medical risk, fraud score)
→ The relationship between features and outcome is roughly linear
→ Model interpretability matters — weights have clear meaning
→ Dataset is large — it scales much better than trees for millions of rows
→ You want a fast, regularizable baseline before trying complex models
?
When does logistic regression fail?
›
Logistic regression struggles when:
→ The decision boundary is genuinely non-linear (XOR problem, concentric circles)
→ Features have complex interactions not captured by linear combination
→ Data has missing values — requires preprocessing
→ Features are not scaled — gradient descent converges slowly

Fix: Add polynomial features, interaction terms — or switch to SVM, Random Forest, or a neural network.

10 · Check your understanding

Quick quiz

Four questions — test yourself on logistic regression.

1. The sigmoid function σ(z) outputs 0.5 when z equals:
A. z = 1
B. z = −1
C. z = 0 ✓
D. z = 0.5
σ(0) = 1/(1+e⁰) = 1/(1+1) = 0.5. When z = 0, the model is maximally uncertain — 50/50. The decision boundary in logistic regression is exactly where z = 0. ✓
2. Why does logistic regression use log-loss instead of mean squared error?
A. Log-loss is easier to compute than MSE
B. Log-loss is convex for logistic regression, guaranteeing a global minimum ✓
C. MSE cannot handle binary labels
D. Log-loss is always smaller than MSE
With sigmoid outputs, MSE creates a non-convex loss landscape with local minima where gradient descent can get stuck. Log-loss (binary cross-entropy) is convex when combined with the sigmoid, so gradient descent is guaranteed to find the global minimum. MSE can handle binary labels, but the optimisation landscape is problematic. ✓
3. In sklearn's LogisticRegression, setting C = 0.001 (very small) will:
A. Disable regularization entirely
B. Apply very weak regularization — allow large weights
C. Apply very strong regularization — shrink weights heavily ✓
D. Switch from L2 to L1 automatically
sklearn uses C = 1/λ, so small C means large λ, which means strong regularization. C = 0.001 heavily penalises large weights, pushing them towards zero. Large C (e.g., C = 1000) means weak regularization — almost no penalty, equivalent to vanilla logistic regression. ✓
4. Logistic regression's decision boundary in the original feature space is always:
A. A curve — the sigmoid is curved
B. A circle — defined by the probability contour
C. A rectangle — like a decision tree split
D. A straight line (or hyperplane in N dimensions) ✓
The decision boundary is where σ(z) = 0.5, which means z = 0, which means w₀ + w₁x₁ + w₂x₂ = 0 — a linear equation. In 2D this is a line, in 3D a plane, in N dimensions a hyperplane. The sigmoid makes the output curved, but the boundary itself is linear. To get non-linear boundaries, you'd need to add polynomial features manually. ✓
