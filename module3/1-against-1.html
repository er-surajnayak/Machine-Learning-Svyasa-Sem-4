One-vs-One (OvO)
Multiclass Classification

Comparing every pair separately to find the overall champion. Learn how to transform simple binary models into a sophisticated multiclass decision engine.

01 · Motivation

The Problem First

Imagine you’re building a model to classify animal images: 👉 Cat 🐱 vs Dog 🐶 vs Cow 🐮.

Most classic machine learning algorithms (like Logistic Regression or SVM) are naturally binary. They are built to separate exactly two classes (YES vs NO). They cannot inherently understand three or more labels at once.

The Solution: Strategies like One-vs-One (OvO) act as a wrapper around these binary models, allowing them to handle multi-class datasets by breaking them into simpler pieces.
02 · Strategy

Core Idea of One-vs-One

Instead of comparing one class against everything else at once (like OvR), OvO takes a more granular approach. It asks: "Why not compare every possible pair separately?"

For our 3-class example (Cat, Dog, Cow), we create specific models for every combination:

  • Matchup 1: Cat vs Dog
  • Matchup 2: Cat vs Cow
  • Matchup 3: Dog vs Cow

Each pair gets its own tiny expert — a binary classifier dedicated just to that specific rivalry.

03 · Scaling Up

How Many Classifiers?

As the number of classes grows, the number of "one-on-one matches" increases combinatorially. The formula for N classes is:

Number of Classifiers = N(N - 1) / 2

04 · Mental Model

Real-Life Analogy: The Cricket Tournament 🏏

Think of it like a Round-Robin tournament:

  • Every team plays against every other team exactly once.
  • Each match produces one winner.
  • The final overall champion is the team with the most wins across all matches.
In ML terms: Each match is a binary classifier. Each win is a vote. The final classification is the class with the highest vote tally.
05 · Workflow

Step-by-Step Working

Step 1: Train Classifiers

Train $N(N-1)/2$ models. For Cat, Dog, Cow:

Model 2Cat vs Cow
Model 3Dog vs Cow

Step 2: Predict for New Input

Show a new image to all models. Each one votes for its own winner:

Step 3: Count Votes & Declare Winner

TallyCat: 1 | Dog: 1 | Cow: 1 (Tie!)

In real systems, ties are broken by looking at confidence scores (which model was "more sure" of its prediction).

06 · The Equation

Mathematical Understanding

For each pair of classes (i, j), we train a binary classifier fi,j. During prediction, the classifier fi,j outputs either class i or class j.

Final Prediction = argmaxk (Total votes for Class k)

This is effectively a Majority Voting scheme where the decision is democratized across many specialized experts.

07 · Advantages

Why OvO Works Well?

Better Focus

Each classifier sees less confusion because it only has to distinguish between two specific classes at a time.

Cleaner Boundaries

Decision boundaries between two classes are often simpler and cleaner than boundaries between one class and "everything else."

Best for: OvO is the standard approach for models that don't scale well with large numbers of samples, such as SVMs (Support Vector Machines).
08 · The Cost

Disadvantages

Computational Explosion

As classes increase, the number of models grows quadratically. 100 classes would require 4,950 classifiers!

Slow Prediction

Making a single prediction takes longer because you have to run the data through every single model created.

11 · Revision

Exam-Ready Notes

Definition (3–5 marks)

"One-vs-One (OvO) is a multiclass classification strategy where a separate binary classifier is trained for every possible pair of classes. For N classes, it creates N(N−1)/2 classifiers. During prediction, each classifier votes for a class, and the final output is determined by the class with the maximum votes."

Quick Summary
  • Converts multiclass to multiple binary problems.
  • Uses a Pairwise comparison approach.
  • Final class = argmax(votes).
  • Standard for SVM models.
One-Line Intuition: "Instead of fighting everyone at once, OvO makes every class fight one-on-one—and picks the overall winner." 🏆
